# Рабочее пространство

Личное веб-приложение: проекты, задачи, документы, примеры, секреты, почта, учёт времени и уведомления. Работают вход, настройки, файлы, очередь событий, планировщик и все модули. Скрипт бэкапа ещё не добавлен.

## Стек

- Python 3.12, FastAPI, SQLAlchemy 2, SQLite (файл `./data/app.db`, режим WAL)
- Vue 3, Vite, vue-router
- Один процесс uvicorn. В Docker он же отдаёт собранный фронтенд

Поведение (интервалы, лимиты, подписи) лежит в настройках, не в константах кода. Секреты процесса — только в `.env`: `SECRET_KEY`, `FERNET_KEY`, каталог данных, уровень логов, учётка первого пользователя.

## Разработка на Windows

Два терминала из корня проекта. Нужны Python 3.12 и Node.js.

```bat
py -3.12 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

```bat
cd frontend
npm install
npm run dev
```

Браузер: `http://localhost:8080`. Vite проксирует `/api` и `/healthz` на порт 8000.

Если `.env` нет, в режиме dev ключи создаются сами и пишутся в `data/bootstrap.env`. Первый пользователь: логин и пароль из `SEED_USERNAME` / `SEED_PASSWORD`. Если пароль не задан — `admin` / `admin`, в лог пишется предупреждение.

Скопируйте `.env.example` в `.env`, когда нужны свои значения.

## Проверка скелета

API на порту 8000, интерфейс на 8080.

1. `GET http://127.0.0.1:8000/healthz` — `status: ok`, модули `db`, `auth`, `settings`, `files`, `outbox`, `scheduler`.
2. Войти: `admin` / `admin` (если пароль не меняли).
3. Обзор показывает состояние модулей и очередь.
4. Настройки: изменить «Название приложения», обновить страницу, вернуть кнопкой «Сбросить».
5. Логи: `data/logs/app.log` (всё выбранного уровня) и `data/logs/errors.log` (предупреждения и ошибки). В строке есть время, уровень, модуль, действие, `request_id`, `user_id`. Пароли в лог не попадают.

`GET /api/auth/me` без сессии возвращает `null` и код 200. Так проверка входа не выглядит как сбой. Закрытые маршруты по-прежнему отвечают 401.

Пример входа из консоли:

```bat
curl -c cookies.txt -H "Content-Type: application/json" -d "{\"username\":\"admin\",\"password\":\"admin\"}" http://127.0.0.1:8000/api/auth/login
curl -b cookies.txt http://127.0.0.1:8000/api/auth/me
```

## Деплой на Ubuntu

На сервере: Docker и Docker Compose.

```bash
cp .env.example .env
# заполнить SECRET_KEY, FERNET_KEY, SEED_PASSWORD
docker compose up -d --build
```

Приложение слушает порт 8000. Каталог `./data` — база, файлы и логи, он смонтирован в контейнер. Процесс один, без отдельного воркера очереди.

Ключ Fernet можно получить так:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

`SECRET_KEY` — длинная случайная строка. В `APP_ENV=prod` без этих двух переменных процесс не стартует.

## Логи

| Файл | Что внутри |
|---|---|
| `data/logs/app.log` | Все сообщения выбранного уровня. Запись, изменение и удаление — INFO. Обычные GET — DEBUG |
| `data/logs/errors.log` | WARNING и ERROR |

## Тесты

Рабочая база не используется: проверки поднимают свой временный файл.

```bat
.venv\Scripts\python -m unittest discover -s tests
cd frontend
npm test
```
| `data/logs/uvicorn.log` | Только локальный запуск сервера разработки |

Ротация по размеру и срок хранения задаются в настройках (`logs.rotation_mb`, `logs.retention_days`). Джоба `logs.cleanup` удаляет файлы старше срока.

Как читать строку:

```text
2026-10-15 21:00:00.000 | INFO     | auth | login | req=ab12 | user=1 | login user_id=1
```

`req` связывает HTTP-запрос, событие outbox и фоновую работу. У джобы `req` вида `job:logs.cleanup:<unix>`.

## Модуль «Проекты»

После входа — список проектов. Создание, правка названия и описания, архив. Карточка показывает открытые и просроченные задачи, ближайший дедлайн, часы за неделю и новые письма. Пока модулей задач, времени и почты нет, на карточке написано «недоступно». Внутри проекта — доска со сводкой, поиск и настройки этого проекта. Остальные пункты меню показывают «Модуль недоступен», само меню не падает.

Проверка:

1. Создать проект, открыть его, изменить название в настройках проекта, отправить в архив.
2. На списке включить «Показать архив» и вернуть проект.
3. Поиск короче минимума (по умолчанию 2 символа) — сообщение об ошибке. Длиннее — группы с пометкой «Модуль недоступен».
4. `GET /healthz` содержит модуль `projects` со статусом `ok`.

## Модуль «Задачи»

На доске проекта — канбан. Колонки создаются вместе с проектом из настройки `tasks.statuses.defaults` (у уже существующего проекта они появляются при запуске модуля). Карточку двигают за «Тащить»: она сразу остаётся в новой колонке, а запись в базу идёт следом. Если сервер ответит ошибкой, появляется окно и карточка возвращается назад.

Прогресс `auto` — доля отмеченных пунктов чеклиста (если пунктов нет, 0). `manual` — число не больше `tasks.progress.max`. Приоритеты и предупреждения о дедлайне тоже из настроек. Джоба `tasks.deadlines` пишет события `task.deadline_soon` и `task.overdue`. Повтор за тот же день не создаётся.

На карточке проекта открытые, просроченные и ближайший дедлайн становятся числами. Часы и почта по-прежнему «недоступно», пока нет своих модулей. Поиск по проекту находит задачи по названию, описанию и меткам, в том числе на русском.

Проверка:

1. Открыть проект: три колонки, график создания и закрытия, пустые ближайшие дедлайны.
2. Добавить задачу, открыть её, отметить два пункта чеклиста — прогресс 100 при максимуме 100. Поставить дедлайн вчера и исполнителя.
3. Перетащить задачу в «Готово». В ленте есть смена колонки.
4. На списке проектов у карточки открытые задачи — число, не «недоступно».
5. Поиск по части названия находит задачу.
6. `GET /healthz` — модуль `tasks` со статусом `ok`, среди джоб есть `tasks.deadlines`.

## Модуль «Документы»

В проекте пункт «Документы»: загрузка файла, название и заметка. Если название пустое, берётся имя файла. У документа несколько версий — новая не затирает старую. Файл лежит в общем хранилище по sha256, связь — в `file_links`.

Текст читается сразу: docx, pdf, xlsx/xlsm и обычный текст (txt, md, csv). Кодировки, число страниц, строк и символов — настройки модуля `documents`. Файл другого типа сохраняется, статус «Формат без разбора». Ошибка разбора не мешает скачать файл; джоба `documents.extract` повторяет такие версии, пока не исчерпает `extract.retry_max`.

На доске проекта блок «Последние документы» ведёт в карточку. Поиск по проекту ищет название, заметку, комментарий версии и извлечённый текст (по умолчанию все версии) и показывает фрагмент.

Проверка:

1. Загрузить docx или pdf с узнаваемой фразой. В карточке статус «Текст извлечён», фраза видна в предпросмотре, файл скачивается.
2. Загрузить вторую версию — номер стал 2, первая осталась в списке.
3. На доске документ в «Последних документах». Поиск по фразе из файла находит его в группе «Документы».
4. Отправить в архив: в списке пропадает, с галкой «Показать архив» возвращается.
5. `GET /healthz` — модуль `documents` со статусом `ok`, среди джоб есть `documents.extract`.

## Модуль «Примеры»

Пункт «Примеры» внутри проекта: название, текст (команда, код или шаблон), заметка, язык, метки и файлы. Язык берётся из настройки `examples.languages`. Если язык не выбран, ставится `language.default`. Свой код языка разрешён, пока включено `language.allow_custom`. Метки в одном поле делятся `tag.separator` (по умолчанию запятая). Закреплённые примеры в списке выше остальных. Архив скрыт, пока не включить «Показать архив».

Поиск по проекту ищет название, заметку, текст и метки и показывает фрагмент. Содержимое в лог не пишется. Отдельной джобы у модуля нет.

Проверка:

1. Добавить пример с фразой в тексте и меткой. Открыть его, скопировать текст, прикрепить файл и скачать его.
2. Закрепить — в списке он выше незакреплённых. Отправить в архив — из списка пропадает.
3. На доске поиск по фразе из текста находит пример в группе «Примеры».
4. `GET /healthz` — модуль `examples` со статусом `ok`.

## Модуль «Секреты»

Пункт «Секреты» внутри проекта: название, вид, логин, ссылка, заметка и сам секрет. Название хранится как есть — по нему работает список и поиск проекта. Логин, ссылка, заметка и секрет пишутся в базу только шифром Fernet (`FERNET_KEY` из `.env`). Смена ключа делает старые записи нечитаемыми.

Карточка секрета не отдаёт само значение, пока не нажать «Показать» или «Копировать». Пустое поле при сохранении секрет не меняет. «Очистить секрет» стирает его. «Сгенерировать» берёт длину и набор символов из настроек `secrets.generator.*`. В лог значение не пишется. Поиск по логину или по секрету ничего не находит.

Проверка:

1. Добавить запись с узнаваемым названием и секретом. В списке секрета нет, в карточке он появляется только после «Показать».
2. Поиск по проекту по части названия находит запись в группе «Секреты». Поиск по самому секрету — нет.
3. Сгенерировать новый секрет, сохранить, снова показать — значение другое.
4. `GET /healthz` — модуль `secrets` со статусом `ok`.

## Модуль «Учёт времени»

Пункт «Учёт времени» внутри проекта. «Старт» и «Стоп» ведут одну запись на пользователя: второй старт останавливает предыдущий таймер, пока включено `timer.autostop`. Забытый таймер закрывает джоба `timetracking.autostop` через `timer.max_open_minutes`.

Ручная запись — дата и минуты. Длительность округляется по `entry.round_to_minutes` и не короче `entry.min_minutes`. К записи можно привязать задачу этого проекта.

На карточке проекта «Часы за неделю» становятся числом. На доске блок «Часы» показывает сегодня, неделю и идущий таймер. Неделя начинается с `week.starts_on` (0 — понедельник). Часовой пояс — `core.ui.timezone`.

Проверка:

1. Нажать «Старт», через несколько секунд «Стоп». В списке запись не короче минимума (по умолчанию 1 минута).
2. Добавить вручную 90 минут. На карточке проекта часы за неделю — число, не «недоступно». На доске в блоке «Часы» есть сегодня и неделя.
3. Запустить таймер и не останавливать его дольше `timer.max_open_minutes` — джоба закроет запись сама. Для проверки интервал джобы можно временно уменьшить.
4. `GET /healthz` — модуль `timetracking` со статусом `ok`, среди джоб есть `timetracking.autostop`.

## Модуль «Почта»

Пункт «Почта» внутри проекта. Ящик IMAP: сервер, порт, SSL, логин, пароль и папка. Пароль пишется в базу только шифром Fernet. «Проверить» входит на сервер и открывает папку, «Забрать» скачивает новые письма. При первом заходе берутся только последние `fetch.initial_limit` писем, дальше — новые относительно последнего UID. Джоба `mail.poll` повторяет забор.

Правило смотрит поле (от кого, кому, тема, текст) и либо сохраняет письмо, либо сразу кладёт в архив, либо не сохраняет. Для сохранённого письма, если действие в списке `rules.notify_actions`, в очередь пишется событие `mail.received` без текста письма.

Файл `.eml` можно загрузить вручную — к нему применяются те же правила. Вложения сохраняются в общее хранилище, если тип файла разрешён. Поиск по проекту ищет тему, адреса и текст. На карточке проекта «Новые письма» — число непрочитанных не из архива.

Проверка:

1. Добавить правило «рассылка» — поле «От кого», содержит адрес, действие «Не сохранять». Загрузить `.eml` от этого адреса: письмо не появляется в списке.
2. Загрузить обычное письмо с узнаваемой фразой в тексте. Оно в списке, на доске в «Последних письмах», поиск по фразе находит его в группе «Письма».
3. Открыть письмо: оно становится прочитанным, счётчик новых писем на карточке уменьшается. Вложение скачивается.
4. Добавить ящик и нажать «Проверить». Ошибка входа показывается у ящика и не содержит пароль.
5. `GET /healthz` — модуль `mail` со статусом `ok`, среди джоб есть `mail.poll`.

## Модуль «Уведомления»

Колокольчик в шапке опрашивает `GET /api/notifications/unread`. Период — настройка `core.ui.poll_notifications_seconds` (по умолчанию 30 секунд). Страница «Уведомления» показывает список и матрицу «событие × канал»: в приложении, Telegram, почта. Матрица сохраняется как настройка пользователя `notifications.matrix`.

События приходят из очереди. Повтор одного и того же `dedup_key` второе уведомление не создаёт. Telegram и SMTP настраиваются в модуле `notifications`: токен бота и пароль SMTP хранятся шифром. Если канал включён, а сервер или токен не задан, доставка помечается «Пропущено» и не повторяется. Ошибка сети остаётся у доставки, джоба `notifications.deliver` пробует снова, пока не исчерпает `delivery.max_attempts`. В лог токен и пароль не пишутся.

Проверка:

1. Создать задачу. Через несколько секунд в колокольчике появляется её название. «Прочитано» уменьшает счётчик.
2. На странице уведомлений выключить канал «В приложении» у «Задача создана» и сохранить. Новая задача в колокольчик уже не попадает.
3. Включить почту или Telegram без сервера и токена, создать событие. У уведомления статус «Пропущено».
4. Указать SMTP на недоступный порт. Статус становится «Ошибка», число попыток растёт, пароля в тексте ошибки нет.
5. `GET /healthz` — модуль `notifications` со статусом `ok`, среди джоб есть `notifications.deliver`.
