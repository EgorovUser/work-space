# Рабочее пространство

Личное приложение для одного человека: проекты и доска задач, документы, примеры, секреты, общая почта, учёт времени и уведомления. Всё крутится одним процессом. Отдельных очередей, Redis и PostgreSQL нет.

Скрипт бэкапа (`sqlite` backup, `data/files` и `.env`) ещё не написан.

## Стек

- Python 3.12, FastAPI (обычные sync-эндпоинты), SQLAlchemy 2, SQLite в режиме WAL
- Vue 3, Vite, vue-router, обычный JavaScript. Состояние — composables, без Pinia
- Стили — свой CSS. Перетаскивание — SortableJS, графики — Chart.js
- Разбор файлов: python-docx, PyMuPDF, openpyxl
- Шифрование секретов и паролей ящика — Fernet (`cryptography`). Пароли входа — bcrypt

База — файл `data/app.db`. Таблицы создаются при старте через `Base.metadata.create_all()`. Alembic нет. Файлы лежат в `data/files`: имя каталога — первые два символа sha256, сам файл — полный хеш. Повторная загрузка тех же байтов новую копию не создаёт.

Поведение (интервалы, лимиты, подписи, колонки по умолчанию) берётся из настроек. В `.env` только то, без чего процесс не живёт: ключи, каталог данных, уровень логов и учётка первого пользователя.

## Каталоги

```text
app/                 бэкенд
  core/              конфиг, база, вход, файлы, настройки, очередь, планировщик
  modules/           projects, tasks, documents, examples, secrets, timetracking, mail, notifications
frontend/            Vue-интерфейс
data/                база, файлы, логи, bootstrap.env (создаётся само)
tests/               проверки бэкенда на временной базе
```

Настройки бывают трёх областей: общие, проекта и пользователя. Секретные значения (токен бота, пароль SMTP, пароль ящика) в интерфейсе не показываются обратно: пустое поле при сохранении их не затирает.

## Разработка на Windows

Нужны Python 3.12 и Node.js. Два терминала из корня проекта.

```bat
py -3.12 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

```bat
cd frontend
npm install
npm run dev
```

Интерфейс: `http://localhost:8080`. Vite проксирует `/api` и `/healthz` на порт 8000.

Если `.env` нет, в режиме dev ключи создаются сами и пишутся в `data/bootstrap.env`. Первый пользователь берётся из `SEED_USERNAME` и `SEED_PASSWORD`. Если пароль не задан — `admin` / `admin`, и в лог пишется предупреждение. Свои значения — скопировать `.env.example` в `.env`.

## Деплой на Ubuntu

На сервере нужны Docker и Docker Compose.

```bash
cp .env.example .env
# заполнить SECRET_KEY, FERNET_KEY, SEED_PASSWORD
docker compose up -d --build
```

Сборка в два шага: Node собирает фронт, затем образ Python. Uvicorn один, без отдельных воркеров, и сам отдаёт собранный фронт. Приложение слушает порт 8000. Каталог `./data` смонтирован в контейнер: там база, файлы и логи.

Ключ Fernet:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

`SECRET_KEY` — длинная случайная строка. При `APP_ENV=prod` без `SECRET_KEY` и `FERNET_KEY` процесс не стартует. Смена `FERNET_KEY` делает уже сохранённые секреты, пароль ящика и пароль SMTP нечитаемыми.

Проверка контейнера — `GET /healthz` каждые 30 секунд.

## Вход

Сессия — cookie. `GET /api/auth/me` без сессии возвращает `null` и код 200, чтобы проверка входа не выглядела как сбой. Остальные закрытые маршруты отвечают 401.

```bat
curl -c cookies.txt -H "Content-Type: application/json" -d "{\"username\":\"admin\",\"password\":\"admin\"}" http://127.0.0.1:8000/api/auth/login
curl -b cookies.txt http://127.0.0.1:8000/api/auth/me
```

`GET http://127.0.0.1:8000/healthz` без входа отдаёт статус процесса, модули и имена джоб.

## Экраны

Слева постоянное меню: Проекты, Почта, Уведомления, Настройки, Состояние. Колокольчик там же.

| Адрес | Что там |
|---|---|
| `/` | Проекты, горящие задачи, новые письма, события из почты на сегодня |
| `/mail` | Общий ящик: письма, переписки, хештеги, ящик IMAP |
| `/mail/:id` | Письмо целиком |
| `/notifications` | Список, матрица «событие × канал», Telegram и SMTP |
| `/settings` | Остальные настройки, по вкладкам модулей |
| `/system` | Живая проверка и расписание джоб |
| `/projects/:id` | Доска проекта |
| `/projects/:id/tasks/:id` | Карточка задачи |
| `.../documents`, `examples`, `secrets`, `mail`, `time`, `settings` | Разделы проекта |

Вкладки проекта: Доска, Документы, Примеры, Секреты, Почта, Учёт времени, Настройки.

Карточку на доске двигают сразу. Если сервер ответит ошибкой, появляется окно и карточка возвращается назад. Колонку двигают за ручку «⋮⋮» в шапке колонки.

## Проекты и задачи

Проект — название, описание, архив. На карточке: открытые и просроченные задачи, ближайший срок, часы за неделю, новые письма.

Колонки создаются из `tasks.statuses.defaults`. У старого проекта они появляются при старте модуля задач. Прогресс `auto` — доля закрытых пунктов чеклиста. `manual` — число не больше `tasks.progress.max`. Джоба `tasks.deadlines` пишет `task.deadline_soon` и `task.overdue`. Повтор за тот же день не создаётся.

К задаче можно прикрепить файл. Он создаётся как документ или пример, в задаче остаётся ссылка.

## Документы

Файл, название, заметка, несколько версий. Новая версия не затирает старую. Текст читается сразу: docx, pdf, xlsx/xlsm, txt, md, csv. Другой тип сохраняется со статусом «Формат без разбора». Ошибка разбора не мешает скачать файл. Джоба `documents.extract` повторяет такие версии, пока не кончится `extract.retry_max`.

Поиск ищет название, заметку и извлечённый текст.

## Примеры

Пример — название, заметка, язык, метки и файлы (pdf, таблицы, картинки, что прислал заказчик). Текст по-прежнему можно хранить. Язык берётся из `examples.languages`. Закреплённые стоят выше. Поиск ищет название, заметку, текст и метки. Содержимое в лог не пишется.

## Секреты

Название хранится открыто — по нему список и поиск. Логин, ссылка, заметка и сам секрет пишутся только шифром. Карточка не отдаёт значение, пока не нажать «Показать». Пустое поле при сохранении секрет не меняет. Генератор берёт длину и набор символов из `secrets.generator.*`. Поиск по секрету или логину ничего не находит. Значение в лог не пишется.

## Учёт времени

Один открытый таймер на пользователя. Второй «Старт» останавливает предыдущий, пока включено `timer.autostop`. Забытый таймер закрывает джоба `timetracking.autostop` через `timer.max_open_minutes`.

Ручная запись — дата и минуты. Длительность округляется по `entry.round_to_minutes` и не короче `entry.min_minutes`. Запись можно привязать к задаче этого проекта.

Неделя учёта начинается с `timetracking.week.starts_on`: 0 — понедельник, 6 — воскресенье. Часовой пояс экрана — `core.ui.timezone` (пусто — зона сервера). `core.ui.week_starts_on` — отдельная настройка интерфейса: там 0 — воскресенье, 1 — понедельник.

## Почта

Ящик один на все проекты. Пароль IMAP хранится шифром. Если пароль не подошёл, повторных попыток нет: ящик блокируется и приходит уведомление, что пароль надо сменить. На странице почты пароль можно заменить и проверить вход, не скачивая всю почту.

Что делает забор (`mail.poll`):

1. Новые письма после последнего UID. О них можно уведомить.
2. Сверка окна `fetch.lookback_days` (от 1 до 30, по умолчанию 7). Чего нет в базе — докачивается без уведомления.
3. Если включён `fetch.backfill`, старые ещё не скачанные письма идут порциями: `fetch.batch_size` писем, `fetch.batches_per_run` порций за один проход. Эти порции тоже молчат.

Письма сохраняются всегда, вложения при первом заходе не качаются: у письма есть пометка, и вложение можно забрать позже.

Фильтр проекта не решает, сохранять письмо или нет. Если письмо подходит, оно относится к проекту. При включённом `filters.move` оно копируется или переносится в IMAP-папку с именем проекта. Папка создаётся, если её нет.

Письма с одной темой (без `Re:`, `Fw:`, «Ответ», «Автоматический ответ» и других приставок из `threads.prefixes`) показываются одной перепиской. Хештеги ставятся правилами, цвет — любой HEX. Ручной кнопки «поставить хештег» в списке нет.

Из писем и вложений `.ics` достаются события. На главном экране видны сегодняшние. Джоба `mail.events` пишет «сегодня» и «скоро».

Письмо показывается вёрсткой в песочнице, не голым текстом.

## Уведомления

Колокольчик опрашивает `GET /api/notifications/unread`. Период — `core.ui.poll_notifications_seconds` (по умолчанию 30 секунд).

Каналы: в приложении, Telegram, почта. Матрица «событие × канал» — настройка пользователя. Токен бота и SMTP задаются на странице уведомлений, не в общих настройках. Там же кнопки проверки: тестовое сообщение в Telegram и тестовое письмо. Если канал включили позже, джоба `notifications.deliver` догоняет недавние события (`delivery.catchup_hours`, пачка `delivery.catchup_batch`).

Ошибка сети повторяется, пока не кончится `delivery.max_attempts`. Если сервер или токен не задан, доставка помечается «Пропущено» и не крутится. Токен и пароль в лог не попадают.

Одно и то же `dedup_key` второе уведомление не создаёт.

Событие `system.status` — «в состоянии что-то не работает». Оно не поднимается из-за самого Telegram, почты уведомлений, очереди доставки и колокольчика. Одиночный сбой молчит: сообщение уходит, если поломка повторилась на следующей проверке. Когда снова всё в порядке, приходит одно сообщение.

## Настройки и база

Страница «Настройки» — вкладки модулей, карточки по три в ряд. Токен бота и SMTP туда не дублируются.

В карточке «База» (вкладка «Общие»):

- сколько ждать, если файл базы занят (`db.busy_timeout_ms`);
- проверять ли целостность на странице состояния (`db.quick_check`);
- путь и размер файла, кнопки «Проверить целостность», «Записать журнал», «Сжать».

Рядом карточка «Следить за состоянием»: писать ли о поломках, как часто смотреть и через сколько часов напомнить о той же.

## Состояние и джобы

Страница «Состояние» каждый раз заново открывает базу, файлы, почту и каналы. Кнопка «Проверить» сама ничего не отправляет.

| Джоба | Что делает | Как часто, настройка |
|---|---|---|
| `mail.poll` | Новые письма, окно последних дней, старые порции | `mail.job.seconds` |
| `mail.events` | «Сегодня» и «скоро» по событиям из писем | `mail.events.check_seconds` |
| `tasks.deadlines` | Близкий срок и просрочка | `tasks.deadlines.interval_seconds` |
| `documents.extract` | Повторный разбор файлов | `documents.extract.retry_seconds` |
| `timetracking.autostop` | Закрывает слишком долгий таймер | `timetracking.timer.job_seconds` |
| `notifications.deliver` | Повтор отправок и догон каналов | `notifications.job.seconds` |
| `system.watch` | Пишет, если сломалось что-то кроме уведомлений | `core.watch.seconds` |
| `logs.cleanup` | Удаляет старые файлы журнала | `core.logs.cleanup_interval_hours` |

Плюс два цикла, которые не джобы планировщика: разбор очереди событий (`core.outbox.poll_seconds`) и опрос колокольчика открытой вкладкой.

## Логи

| Файл | Что внутри |
|---|---|
| `data/logs/app.log` | Сообщения выбранного уровня. Запись, изменение, удаление и ответы с ошибкой — INFO. Обычный GET — DEBUG |
| `data/logs/errors.log` | WARNING и ERROR |
| `data/logs/uvicorn.log` | Вывод процесса при локальном запуске |

Ротация — `logs.rotation_mb`, срок — `logs.retention_days`.

```text
2026-10-15 21:00:00.000 | INFO     | auth | login | req=ab12 | user=1 | login user_id=1
```

`req` связывает HTTP-запрос, событие очереди и фоновую работу. У джобы он вида `job:mail.poll:<unix>`. Пароли, токены и значения секретов в текст лога не попадают.

## Тесты

Рабочая база не используется: проверки поднимают свой временный файл.

```bat
.venv\Scripts\python -m unittest discover -s tests
cd frontend
npm test
```

На бэкенде проверяются вход, проект и порядок колонок, секрет, дедупликация файла, границы настроек, фильтр почты, разбор письма и календаря, склейка тем и то, что поломка самих уведомлений отдельное уведомление не поднимает. На фронте — формат даты, перенос карточки и одно открытое меню.
