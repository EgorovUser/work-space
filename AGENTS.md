# AGENTS.md — контракт репозитория для ИИ-агентов

Это личное приложение одного человека (проекты/задачи, документы, секреты, общая
почта, учёт времени). Прочитайте этот файл целиком, прежде чем менять код.

Историческая справка: проект был экспортирован из Grok App Builder. Все
платформенные артефакты того окружения (`.grok/`, корневые `src/`, `public/`,
`server/`, `package.json`, `vite.config.ts`, `vercel.json`, `startup.sh`,
`screenshots/`) удалены. Приложение живёт только в `app/` и `frontend/`.

## Стек и структура

- **Бэкенд** `app/` — Python 3.12, FastAPI (sync-эндпоинты), SQLAlchemy 2,
  SQLite (WAL). Модули: projects, tasks, documents, examples, secrets, rdp,
  timetracking, mail, notifications. Ядро: `app/core/` (конфиг, база, вход,
  файлы, настройки, очередь, планировщик, версия сборки `app/core/version.py`). Живые события для открытых
  вкладок — `app/core/events_bus.py` (внутрипроцессная шина) и
  `app/core/sse.py` (канал `/api/events`): джобы и обработчики публикуют
  сигналы `mail.changed` / `mail.sync` / `notifications.changed`, канал сам
  пересчитывает счётчики и пересылает `mail.sync`/`mail.changed` именованными
  событиями (открытые вкладки обновляют список без F5). Брокеров не заводить
  — см. «Чего не делать».
- **Фронтенд** `frontend/` — Vue 3 + Vite, обычный JavaScript, composables без
  Pinia, свой CSS. Прокси `/api` и `/healthz` на порт 8000. Навигация — два
  этажа: рельса несёт только глобальные разделы («Сегодня», «Проекты»,
  «Почта», «Секреты», «Корзина», «Уведомления», «Настройки», «Состояние»),
  разделы проекта — горизонтальные табы под шапкой (`views/ProjectLayout.vue`, класс
  `.project-tabs`; на телефоне лента скроллится вбок). Главная — хаб
  «Сегодня» (`views/Today.vue`, данные `/api/home`): просроченные и
  ближайшие сроки, события, свежая почта, уведомления, быстрый список
  проектов; список проектов живёт отдельно на `/projects`. Командная
  палитра — Ctrl+K/Cmd+K в любом месте (`components/GlobalSearch.vue`);
  у каждого результата подписан его проект (патч P — до перехода,
  не после).
  «Секреты» —
  общий список секретов всех проектов (`views/SecretsGlobal.vue`, данные
  `/api/secrets`: группы по проектам, поиск по названию, лимит
  `secrets.list.global_limit`; значения не расшифровываются — копирование
  логина и секрета идёт существующими проектными эндпоинтами). «Почта» —
  master-detail: список и читалка рядом (`views/Mailbox.vue` + компонент
  `components/MailReader.vue`), выбранное письмо живёт в маршруте `/mail/:id`.
  «Задачи» проекта — доска или календарь (`components/TaskBoard.vue` /
  `components/TaskCalendar.vue`, вид в URL: `?view=calendar`). Повторяющиеся
  задачи (daily/weekly/monthly/yearly, «каждые N», граница «до даты»)
  при закрытии создают следующее вхождение — логика в
  `app/modules/tasks/service/recurrence.py`, событие ленты `recur`, уведомление
  `task.recurred`.
- **Секреты: история значений** (патч O) — каждое обновление, реально
  меняющее пароль, логин или ссылку, сохраняет снимок прежнего состояния
  в `secret_revisions` (то же Fernet-шифрование). Страница секрета
  (`views/SecretPage.vue`) показывает блок «История значений»: скопировать
  прежний пароль (буфер чистится через 30 с) или вернуть версию — откат
  не разрушающий, текущие значения тоже становятся снимком. Тост после
  сохранения несёт кнопку «Отменить» (мгновенный откат через
  `…/revisions/{id}/restore`). Слепые перезаписи — «Сгенерировать» и
  «Очистить секрет» поверх заданного значения — сначала спрашивают
  подтверждение. Глубина истории — `secrets.history.keep_revisions`
  (по умолчанию 10). Проверка доступности RDP (пинг) удалена: за
  корпоративным VPN она бессмысленна.
- **Корзина** (патч N, расширяется патчем P) — мягко удалённые
  задачи/документы/секреты/RDP-подключения (`views/Trash.vue`, данные
  `/api/trash`): у каждой записи — сколько дней осталось до автоочистки
  (days_left, ceil до retention), «Восстановить» и «Удалить навсегда»;
  «Очистить всё» (`DELETE /api/trash`) вычищает все типы разом теми же
  сервисами, что и одиночное удаление. Джоба `trash.purge` убирает
  просроченное по `trash.retention_days`.
- **RDP-подключения** — раздел проекта `views/Rdp.vue` (данные
  `/api/projects/{id}/rdp`): название, адрес, порт, логин, домен, заметка.
  Пароль не хранится: эндпоинт `…/rdp/{id}/file` собирает .rdp на сервере
  (без строки пароля, `prompt for credentials:i:1`), Windows сам спрашивает
  учётные данные при подключении. Правка важных полей (адрес, порт, логин,
  домен, связка с секретом) подтверждается диалогом «было → станет».
  Подключения проиндексированы в общем
  FTS5-поиске (по адресу тоже). Сборка приложения — буква патча из
  `app/core/version.py`: видна в `/healthz` (поле build) и под кнопкой
  «Выйти» в рельсе («сборка P»).
- **PWA** — приложение устанавливается на телефон/десктоп: манифест и иконки
  в `frontend/public/` (иконки генерирует `scripts/make_pwa_icons.py`,
  PyMuPDF), сервис-воркер `frontend/public/sw.js` (навигация — сеть с офлайн-
  фолбэком в кеш, `/assets/*` — cache-first, `/api/*` — всегда мимо кеша).
  Бэкенд раздаёт `sw.js` с `Cache-Control: no-cache` и манифест с верным
  MIME (`app/main.py: _mount_frontend`). На узких экранах — нижняя навигация
  (`components/BottomNav.vue`: «Сегодня»/«Проекты»/«Почта»/«Секреты»/
  «Уведомления»/«Настройки»; глобальная часть рельсы на телефоне скрыта
  CSS) и тач-таргеты 44px. Регистрация — инлайном в `frontend/index.html`
  (только https/localhost).
- **Миграции** — Alembic (`alembic/versions/`). `0001` — baseline-заглушка
  (схема = `create_all`); дальше — реальные миграции. Новые изменения моделей
  оформлять миграцией, а не правкой `create_all`.
- **Тесты** — `tests/` (unittest, 133 проверки; запускаются на временной базе;
  PWA-раздача — только при собранном `frontend/dist`, иначе скип) и
  `frontend/e2e/` (Playwright против настоящего uvicorn, 41 сценарий:
  `cd frontend && npm run test:e2e`, нужен собранный `dist`). Юнит-тесты
  фронтенда — `cd frontend && npm test` (42 проверки, node --test).
- **Скрипты** — `scripts/backup.sh` (бэкап SQLite через `.backup` + `data/files`
  + `.env`; запускается на хосте, не в контейнере).

## Как запускать проверки (обязательно перед сдачей работы)

```bash
python -m venv .venv && . .venv/bin/activate   # или .venv\Scripts\activate
pip install -r requirements.txt -r requirements-dev.txt
DATABASE_URL= python -m unittest discover -s tests   # бэкенд, все зелёные
cd frontend && npm install && npm test               # фронтенд, все зелёные
```

Если в окружении есть переменная `DATABASE_URL`, тесты способны подхватить её и
упасть на невалидном значении — запускайте с пустой: `DATABASE_URL= python -m
unittest discover -s tests`.

Проверка импорта приложения: `python -c "import app.main"` (из корня) — должно
проходить без ошибок.

## Контракт базы данных (не ломать)

`app/core/db.py: init_db()` имеет три ветки:

1. **Свежая база** (нет таблиц) — `create_all()` + `stamp("head")`.
2. **Старая до-alembic база** (таблицы есть, `alembic_version` нет) —
   `create_all()` + `stamp("0001")` + `upgrade("head")`: реальные миграции
   0002+ проигрываются по существующим данным.
3. **Управляемая база** — обычный `upgrade("head")`.

После миграций `init_db()` сверяет колонки моделей с фактическими в БД и при
дрейфе пишет WARNING «Схема БД отстала от моделей». Увидели его в логах —
значит, забыли миграцию для новой колонки. CI на это не ругается, но менять
схему без миграции запрещено.

## Правила кода

- Стиль: короткие явные функции, никаких «магических» глобальных состояний.
- Сообщения логов и ошибок — на русском (как существующие).
- API возвращает JSON; делить большие модули на пакеты `service/` с фасадом
  `__init__.py`, реэкспортирующим публичные имена (см. `app/modules/tasks/`,
  `app/modules/mail/`).
- Секреты (токены, пароли SMTP/ящика) шифруются Fernet; в ответах API не
  возвращаются; в логах маскируются.
- Небезопасная разметка писем проходит через санитайзер
  (`app/modules/mail/…/sanitize*`): расширяете фильтры — добавляйте тесты в
  `tests/test_sanitize.py`.

## Рабочий процесс (у агента нет push-доступа)

1. Изменения делаются локальными коммитами в `main` (Conventional Commits).
2. Деливерабл — `git format-patch -1 <commit>`; патч отдаётся пользователю,
   он применяет его через `git am` и пушит сам.
3. Один патч = одна логическая правка. Смешивать рефакторинг и фичи в одном
   коммите нельзя.
4. Каждый патч поднимает букву сборки в `app/core/version.py` (PATCH_ID):
   она попадает в `/healthz` и в интерфейс под кнопкой «Выйти» — это дешёвый
   способ отличить свежую версию от устаревшего образа или кеша браузера.
5. Перед выдачей патча прогнать тесты и проверку импорта (см. выше).

## Чего не делать

- Не удалять и не «улучшать» `scripts/backup.sh` без явной просьбы — им
  пользуется cron на сервере.
- Не заводить Redis/брокеры/PostgreSQL — приложение сознательно однопроцессное.
- Не выносить секреты в код и не создавать `.env` в репозитории (только
  `.env.example`).
- Не менять формат базы без миграции Alembic (см. контракт выше).
- `data/` не трогать: это runtime-каталог (база, файлы, логи, бэкапы).
