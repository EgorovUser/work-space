# AGENTS.md — контракт репозитория для ИИ-агентов

Это личное приложение одного человека (проекты/задачи, документы, секреты, общая
почта, учёт времени). Прочитайте этот файл целиком, прежде чем менять код.

Историческая справка: проект был экспортирован из Grok App Builder. Все
платформенные артефакты того окружения (`.grok/`, корневые `src/`, `public/`,
`server/`, `package.json`, `vite.config.ts`, `vercel.json`, `startup.sh`,
`screenshots/`) удалены. Приложение живёт только в `app/` и `frontend/`.

## Стек и структура

- **Бэкенд** `app/` — Python 3.12, FastAPI (sync-эндпоинты), SQLAlchemy 2,
  SQLite (WAL). Модули: projects, tasks, documents, examples, secrets, rdp,
  timetracking, mail, notifications. Ядро: `app/core/` (конфиг, база, вход,
  файлы, настройки, очередь, планировщик, версия сборки `app/core/version.py`). Живые события для открытых
  вкладок — `app/core/events_bus.py` (внутрипроцессная шина) и
  `app/core/sse.py` (канал `/api/events`): джобы и обработчики публикуют
  сигналы `mail.changed` / `mail.sync` / `notifications.changed`, канал сам
  пересчитывает счётчики и пересылает `mail.sync`/`mail.changed` именованными
  событиями (открытые вкладки обновляют список без F5). Брокеров не заводить
  — см. «Чего не делать».
- **Фронтенд** `frontend/` — Vue 3 + Vite, обычный JavaScript, composables без
  Pinia, свой CSS: `src/styles.css` — индекс из `@import` (патч AP),
  порядок импорта = порядок каскада, сами правила в `src/styles/`
  (base/shell/layout/controls/lists/today/board/mail/feedback/
  responsive/states/focus/search/calendar/pwa). Новая секция — новый
  файл в `styles/`; переставлять правила между файлами нельзя — бандл
  собирается в исходном порядке (проверено побайтовым сравнением). Прокси `/api` и `/healthz` на порт 8000. Навигация — два
  этажа: рельса несёт только глобальные разделы («Сегодня», «Проекты»,
  «Почта», «Секреты», «Корзина», «Уведомления», «Настройки», «Состояние»),
  разделы проекта — горизонтальные табы под шапкой (`views/ProjectLayout.vue`, класс
  `.project-tabs`; на телефоне лента скроллится вбок). Табы рендерятся своими
  `<a>` через `router-link custom` + `isTabActive`: дефолтные классы vue-router
  считают ссылку на индекс-маршрут `/projects/N` активной на любом дочернем
  разделе, и «Доска» подсвечивалась рядом с текущей вкладкой (патч Q); «Доска»
  горит на самой доске и на страницах задач, остальные — и на подстраницах. Главная — хаб
  «Сегодня» (`views/Today.vue`, данные `/api/home`): просроченные и
  ближайшие сроки, события, свежая почта, уведомления, быстрый список
  проектов; список проектов живёт отдельно на `/projects`. Командная
  палитра — Ctrl+K/Cmd+K в любом месте (`components/GlobalSearch.vue`);
  у каждого результата подписан его проект (патч P — до перехода,
  не после). Поле поиска растянуто на весь контейнер шапки
  (`input[type=search]` включён в базовые стили полей, патч Q).
  «Секреты» —
  общий список секретов всех проектов (`views/SecretsGlobal.vue`, данные
  `/api/secrets`: группы по проектам, поиск по названию, лимит
  `secrets.list.global_limit`; значения не расшифровываются — копирование
  логина и секрета идёт существующими проектными эндпоинтами). «Почта» —
  master-detail: список и читалка рядом (`views/Mailbox.vue` + компонент
  `components/MailReader.vue`), выбранное письмо живёт в маршруте `/mail/:id`;
  базовое окно всегда открывается на вкладке «Письма» (патч AI) —
  автопереброс на «Ящик» при пустом списке ящиков убран, глубокие
  ссылки `?tab=` работают по-прежнему.
  «Задачи» проекта — доска или календарь (`components/TaskBoard.vue` /
  `components/TaskCalendar.vue`, вид в URL: `?view=calendar`). Карточка на
  доске — отдельный компонент `components/TaskCard.vue` (патч R): под
  заголовком чипы (приоритет цветом, дедлайн краснеет при просрочке),
  чеклист подзадач с отметкой прямо на доске (до 5 пунктов, «Ещё N»
  разворачивает), поле «ч» + кнопка «Списать» для быстрой записи часов
  (предел одной записи — 99 часов, патч AJ) и
  бейдж «⏱ N ч» всего списанного. У задач с ручным прогрессом вместо
  полоски — компактное поле `input.tc-progress` (патч AK): число,
  Enter, PATCH `progress_manual` тем же эндпоинтом, что форма «О
  задаче». Классы `.task-card`/`.task-meta`/
  `.task-title` и атрибут `data-id` сохранены — на них держатся
  драг-перетаскивание и e2e. Компонент меняет переданный объект задачи на
  месте (это элемент реактивного массива доски), прогресс пересчитывает
  той же формулой, что сервис `_progress`. Список доски (`list_tasks`)
  несёт пункты чеклиста и `spent_minutes` (сумма записей всех
  пользователей, батч-запросом `_spent_by_tasks`); `get_task` тоже
  отдаёт `spent_minutes`. Повторяющиеся
  задачи (daily/weekly/monthly/yearly, «каждые N», граница «до даты»)
  при закрытии создают следующее вхождение — логика в
  `app/modules/tasks/service/recurrence.py`, событие ленты `recur`, уведомление
  `task.recurred`.
- **Один активный фокус** (патч AL): таймер или помодоро — что-то одно.
  Старт помодоро гасит серверный таймер (клиент, лучшим усилием), старт
  таймера («Учёт» проекта или страница задачи) гасит помодоро. Глобальные
  эндпоинты `GET /api/time/running` и `POST /api/time/stop` не привязаны к
  проекту; рельса показывает активный фокус строкой над именем
  пользователя (`.rail-focus`: часы, задача, стоп), в узкой раскладке —
  чипом в шапке. Состояние фронта — `composables/useRunningTimer.js`
  (опрос 20 с + локальный тик часов).
- **Уведомления фокуса** (патч AM): серверный таймер сообщает каждый
  полный час — джоба «Час по таймеру» (timetracking.hours, тот же кадр,
  что автостоп) ставит событие `time.hour_passed` с дедуп-ключом
  `time.hour.<запись>.<час>` (повторные проходы молчат). Тексты: «По
  таймеру прошёл N час/часа/часов», предмет — задача или заметка,
  ссылка — на страницу задачи. Подписка и каналы — как у любого события
  в матрице уведомлений (браузер по умолчанию, Telegram/почта — по
  желанию). Фазы помодоро — системные уведомления браузера («Пора
  отдохнуть», «Отдых закончился»), работают и в фоновой вкладке;
  тумблер «уведомлять о смене фаз» в карточке помодоро запрашивает
  разрешение при включении.
- **Системные уведомления** (патч AO) — тосты Windows из браузера
  (Web Notifications API) для событий вкладки «Уведомления». Канал `os`
  в матрице (по умолчанию выключен — требует разрешения), доставка
  клиентская: `delivery.handle` после создания уведомления публикует
  адресное `notifications.new` (id, заголовок, текст, ссылка, флаг os),
  SSE пересылает его именованным событием. Показывает
  `composables/useOsNotify.js`: тумблеры устройства — localStorage
  («показывать» и «только когда вкладка не на экране»), разрешение
  запрашивает карточка «Системные уведомления» на вкладке «Куда писать»
  (кнопка видна только при permission=default, denied лечится в
  настройках сайта). Несколько вкладок слушают один SSE — тост
  показывает владелец Web Lock (запас — аренда в localStorage с
  сердцебиением), от дублей страхует tag `ws-<id>`. Работает, пока
  открыта хоть одна вкладка/окно; «без вкладки» — это Push API с
  ключами, сознательно не заводили. Канал os не пишет строки
  `NotificationDelivery` (мимолётный тост нечего ретраить и догонять);
  forced-каналы `mail.auth_failed` включают и его.
- **Секреты: история значений** (патч O) — каждое обновление, реально
  меняющее пароль, логин или ссылку, сохраняет снимок прежнего состояния
  в `secret_revisions` (то же Fernet-шифрование). Страница секрета
  (`views/SecretPage.vue`) показывает блок «История значений»: скопировать
  прежний пароль (буфер чистится через 30 с) или вернуть версию — откат
  не разрушающий, текущие значения тоже становятся снимком. Тост после
  сохранения несёт кнопку «Отменить» (мгновенный откат через
  `…/revisions/{id}/restore`). Слепые перезаписи — «Сгенерировать» и
  «Очистить секрет» поверх заданного значения — сначала спрашивают
  подтверждение. Глубина истории — `secrets.history.keep_revisions`
  (по умолчанию 10). Проверка доступности RDP (пинг) удалена: за
  корпоративным VPN она бессмысленна.
- **Корзина** (патч N, расширяется патчем P) — мягко удалённые
  задачи/документы/секреты/RDP-подключения (`views/Trash.vue`, данные
  `/api/trash`): у каждой записи — сколько дней осталось до автоочистки
  (days_left, ceil до retention), «Восстановить» и «Удалить навсегда»;
  «Очистить всё» (`DELETE /api/trash`) вычищает все типы разом теми же
  сервисами, что и одиночное удаление. Джоба `trash.purge` убирает
  просроченное по `trash.retention_days`.
- **RDP-подключения** — раздел проекта `views/Rdp.vue` (данные
  `/api/projects/{id}/rdp`): название, адрес, порт, логин, домен, заметка.
  Пароль не хранится: эндпоинт `…/rdp/{id}/file` собирает .rdp на сервере
  (без строки пароля, `prompt for credentials:i:1`), Windows сам спрашивает
  учётные данные при подключении. Правка важных полей (адрес, порт, логин,
  домен, связка с секретом) подтверждается диалогом «было → станет».
  Подключения проиндексированы в общем
  FTS5-поиске (по адресу тоже). Сборка приложения — буква патча из
  `app/core/version.py`: видна в `/healthz` (поле build) и под кнопкой
  «Выйти» в рельсе (сейчас — «сборка AI»).
- **Списание времени в часах** (патч R) — пользователь вводит часы
  («1.5» — полтора часа), API хранит минуты; конвертация и подписи —
  в одном месте `frontend/src/composables/timeFormat.js`
  (`hoursToMinutes`, `formatHoursCompact` «1,5 ч» для бейджей,
  `formatDuration` «1 ч 30 мин» для списков). Блок «Списать время»
  живёт на главной вкладке «О задаче» (`views/TaskPage.vue`, отдельной
  вкладки «Время» больше нет): часы + дата + заметка, «Списать» /
  «Старт таймера», список последних записей и итог «Всего». Быстрое
  списание — прямо на карточке доски (см. TaskCard выше). Ручная запись
  и правка в разделе «Учёт времени» (`views/Time.vue`) тоже в часах.
  Помодоро на «Сегодня» (`composables/usePomodoro.js`, один таймер на
  всё приложение) списывает время сам по окончании фокуса; задача для
  фокуса выбирается живым поиском по всем открытым задачам всех
  проектов (патч AF): `GET /api/tasks/search` (`app/modules/tasks/
  service/search.py`) — тот же FTS5-индекс и те же правила совпадения,
  что у общего поиска; закрытые, удалённые в корзину и задачи архивных
  проектов в выдачу не попадают. Фронт — `components/TaskPicker.vue`
  (дебаунс, стрелки/Enter/Esc), выбранная задача — чип с крестиком.
- **Тосты на все изменения** (патч R) — любое мутирующее действие
  подтверждается всплывающим тостом `useNotice().show(…, { kind: "success" })`:
  создание/сохранение/удаление в секретах, документах, примерах, задачах,
  заметках, проектах, почте (ящики/правила/хештеги), настройках, записях
  времени. Мягкие удаления (задачи/документы/секреты) несут кнопку
  «Отменить» — восстановление из корзины через `POST /api/trash/{kind}/{id}/
  restore`; тост глобальный (рендерится в `App.vue` поверх маршрута),
  переживает переход со страницы. Примеры и заметки удаляются окончательно
  (без отката), почтовые ящики/правила — тоже. Скелет удаления живёт в одном
  месте — `composables/useSoftDelete.js` (патч AD): подтверждение → DELETE →
  тост с «Отменить» (если у вида есть restore) или простой тост; экраны
  передают тексты и адреса, оптимистичное снятие строки — на их стороне.
  Конфликт версий 409 на страницах правки обрабатывает
  `composables/useConflictedSave.js`.
- **Сводка времени по всем проектам** (патчи S, AB) — «Учёт времени» в
  рельсе ведёт на `/time` (`views/TimeGlobal.vue`): две недели (текущая и
  прошлая, границы — `timetracking.week.starts_on`, по умолчанию пн–вс),
  часы по проектам и записи «что сделано» с задачами и заметками. Бэкенд —
  `GET /api/time/overview` (`app/modules/timetracking/service/overview.py`),
  три запроса на сводку: записи интервала одним SELECT, проекты одним,
  заголовки задач одним батчем IN (без N+1).
- **Счётчики навигации** (патчи T, U, AA, AC) — числа для бейджей живёт
  в одном хабе `app/core/counters.py`: `GET /api/counters[?project_id=]`.
  Модули регистрируют провайдеров в `setup()` роутера
  (`register_global_counters` / `register_project_counters`): глобальные —
  почта/уведомления/корзина/секреты, проектные — документы/примеры/секреты/
  RDP/письма по правилам/заметки (GROUP BY по всем проектам сразу, проект
  без активных записей остаётся с нулём). Кеш с TTL
  `core.counters.ttl_seconds` (15 с), инвалидация из точек мутаций:
  `touch_project()` и publish-обёртки mail/notifications зовут
  `counters.invalidate()`, SSE после сигнала пересчитывает force=True и
  пишет в кеш (write-through). Фронт — `composables/useCounters.js`:
  SSE state, хук мутаций в `api.js` (не-GET → отложенный bump 800 мс),
  router.afterEach, опрос раз в минуту только у видимой вкладки, окно
  свежести 25 с. Бейджи: табы проекта 0–9/«9+»
  (`composables/countFormat.js`), рельса и нижняя навигация 0–99/«99+».
  Цвета (патч AH): обычные счётчики — нейтральный спокойный чип (рельса —
  подложка `--rail-line`, бумага — `--line`), ноль — просто приглушённая
  цифра без чипа; красный кружок (`.alert`, `--badge`) остаётся только у
  непрочитанных уведомлений — класс вешают AppShell и BottomNav, когда
  счётчик не ноль.
- **FTS5-целостность** (патч Y) — «malformed inverted index» от
  `PRAGMA quick_check` на живых индексах — известная ложь старых SQLite
  (до ~3.44; в python:3.12-slim сидит 3.40.1), из-за неё статус «сам
  ломался и сам чинился». Что сделано: жалоба проверяется родной командой
  FTS5 `integrity-check`; цел — строчка уходит (ложная тревога), битый —
  индекс пересобирается из источника (`app/core/search.py:
  rebuild_search_table` — DELETE+INSERT, при нечитаемых сегментах
  DROP+CREATE+INSERT); вручную — кнопка «Пересобрать поиск» в «Состоянии»
  (`POST /api/system/db/reindex`). В проде SQLite свежий:
  `requirements.txt` ставит pysqlite3-binary, `app/__init__.py` подменяет
  им stdlib sqlite3, когда он новее системного; реальная версия пишется
  в лог при старте.
- **Сервисы — пакеты `service/`** (патчи V, W) — монолитных `service.py`
  больше нет: каждый модуль разбит на тематические файлы, фасад
  `service/__init__.py` реэкспортирует имена, потребители импортируют
  `from app.modules.X import service` как раньше. Общие хелперы бэкенда —
  в ядре: `app/core/entities.py` (`owned_row` — загрузка строки с проектом
  и корзиной), `app/core/text.py` (чистка имён, поиск, сниппеты, каталоги);
  модули держат тонкие обёртки. Новые функции пишите в подходящий файл
  пакета, а не возвращайте монолит; общий код — в core, не в соседний модуль.
- **Крупные компоненты — оркестраторы** (патч X, AD) — TaskPage/Mailbox/
  TaskBoard/SecretPage — тонкие виды, содержимое живёт в
  `components/task/`, `components/mail/`, `components/secret/`.
  Общие скелеты фронтенда — в `composables/`: useSoftDelete, useClipboard,
  useConflictedSave, useBoardDrag, countFormat, mailTagStyle. Новые экраны
  зовут их, а не копируют скелет.
- **PWA** — приложение устанавливается на телефон/десктоп: манифест и иконки
  в `frontend/public/` (иконки генерирует `scripts/make_pwa_icons.py`,
  PyMuPDF), сервис-воркер `frontend/public/sw.js` (навигация — сеть с офлайн-
  фолбэком в кеш, `/assets/*` — cache-first, `/api/*` — всегда мимо кеша).
  Бэкенд раздаёт `sw.js` с `Cache-Control: no-cache` и манифест с верным
  MIME (`app/main.py: _mount_frontend`). На узких экранах — нижняя навигация
  (`components/BottomNav.vue`: «Сегодня»/«Проекты»/«Почта»/«Секреты»/
  «Уведомления»/«Настройки»; глобальная часть рельсы на телефоне скрыта
  CSS) и тач-таргеты 44px. Регистрация — инлайном в `frontend/index.html`
  (только https/localhost).
- **Миграции** — Alembic (`alembic/versions/`). `0001` — baseline-заглушка
  (схема = `create_all`); дальше — реальные миграции. Новые изменения моделей
  оформлять миграцией, а не правкой `create_all`.
- **Тесты** — `tests/` (unittest, 173 проверки; запускаются на временной базе;
  PWA-раздача — только при собранном `frontend/dist`, иначе скип) и
  `frontend/e2e/` (Playwright против настоящего uvicorn, 51 сценарий:
  `cd frontend && npm run test:e2e`, нужен собранный `dist`). Юнит-тесты

- **Скрипты** — `scripts/backup.sh` (бэкап SQLite через `.backup` + `data/files`

## Контракт базы данных (не ломать)

`app/core/db.py: init_db()` имеет три ветки:

1. **Свежая база** (нет таблиц) — `create_all()` + `stamp("head")`.
2. **Старая до-alembic база** (таблицы есть, `alembic_version` нет) —
   `create_all()` + `stamp("0001")` + `upgrade("head")`: реальные миграции
   0002+ проигрываются по существующим данным.
3. **Управляемая база** — обычный `upgrade("head")`.

После миграций `init_db()` сверяет колонки моделей с фактическими в БД и при
дрейфе пишет WARNING «Схема БД отстала от моделей». Увидели его в логах —
значит, забыли миграцию для новой колонки. CI на это не ругается, но менять
схему без миграции запрещено. Единственного исторического нарушителя больше
нет: доколонки, которые почта и сторож состояния делали рантайм-DDL
(`ensure_schema`, ALTER в `_note`), переехали в миграцию 0010 (патч AR) —
самописного DDL в рантайме не осталось.

## Правила кода

- Стиль: короткие явные функции, никаких «магических» глобальных состояний.
- Каналы уведомлений — реестр `app/modules/notifications/channels.py`
  (патч AQ): новый канал = `ChannelDef(...)` + одна строка
  `register_channel`, каталог/матрица/доставка/кнопка «Проверить»
  подхватывают его сами (if/elif-диспетчеров больше нет). Клиентские
  каналы (browser — лента, os — системный тост) живут там же с
  `server_delivery=False`: серверных строк доставок не создают.
- Переопределяя базовые стили полей (`input[type=…]`, специфичность 0-1-1),
  селектор компонента должен быть не слабее базового: голого класса мало —
  его молча перебьёт базовое правило. Прецедент: поле часов на карточке
  доски растянулось на всю карточку и вытолкнуло кнопку (патч AJ, теперь
  `input.tc-hours`, вёрстку охраняет e2e в `board.spec.js`).
- Сообщения логов и ошибок — на русском (как существующие).
- API возвращает JSON; делить большие модули на пакеты `service/` с фасадом
  `__init__.py`, реэкспортирующим публичные имена (см. `app/modules/tasks/`,
  `app/modules/mail/`).
- Секреты (токены, пароли SMTP/ящика) шифруются Fernet; в ответах API не
  возвращаются; в логах маскируются.
- Небезопасная разметка писем проходит через санитайзер
  (`app/modules/mail/…/sanitize*`): расширяете фильтры — добавляйте тесты в
  `tests/test_sanitize.py`.

## Рабочий процесс (у агента нет push-доступа)

1. Изменения делаются локальными коммитами в `main` (Conventional Commits).
2. Деливерабл — `git format-patch -1 <commit>`; патч отдаётся пользователю,
   он применяет его через `git am` и пушит сам.
3. Один патч = одна логическая правка. Смешивать рефакторинг и фичи в одном
   коммите нельзя.
4. Каждый патч поднимает букву сборки в `app/core/version.py` (PATCH_ID):
   она попадает в `/healthz` и в интерфейс под кнопкой «Выйти» — это дешёвый
   способ отличить свежую версию от устаревшего образа или кеша браузера.
5. Перед выдачей патча прогнать тесты и проверку импорта (см. выше).

## Чего не делать

- Не удалять и не «улучшать» `scripts/backup.sh` без явной просьбы — им
  пользуется cron на сервере.
- Не заводить Redis/брокеры/PostgreSQL — приложение сознательно однопроцессное.
- Не выносить секреты в код и не создавать `.env` в репозитории (только
  `.env.example`).
- Не менять формат базы без миграции Alembic (см. контракт выше).
- `data/` не трогать: это runtime-каталог (база, файлы, логи, бэкапы).
